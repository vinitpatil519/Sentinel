# Hardware

Everything that runs *off* the console: the firmware on the sensing nodes, and the
setup for the machine that hosts the stack.

| Folder | What it is |
|---|---|
| [`esp32-csi-node/`](esp32-csi-node/) | ESP-IDF firmware for the ESP32-S3 CSI nodes, plus host-side provisioning and probe tools |
| [`jetson/`](jetson/) | Jetson Orin Nano setup script, systemd units, compose override, and an automated first-light check |

## Bring-up order

1. **Host.** Clone the repo on the Jetson (or any Ubuntu machine) and follow
   [`jetson/README.md`](jetson/README.md) → Quick start.
2. **Nodes.** Install ESP-IDF v5.4, then build, flash and provision each board
   per [`esp32-csi-node/README.md`](esp32-csi-node/README.md).
   `tools/flash-node.sh` does flash + provision in one step.
3. **Verify.** `./hardware/jetson/check-stack.sh --expect-nodes <n>`, then the
   console's **RF / Nodes** screen.

Not in the repo, by design — each machine makes its own: the ESP-IDF toolchain
(`flash-node.sh` looks in `~/esp/esp-idf`, or set `IDF_PATH`), `sdkconfig` and
the `build*/` directories (generated by `idf.py` from `sdkconfig.defaults`), and
the session database.

## Why there is a firmware here at all

RuView publishes prebuilt node binaries, and using them is a valid path. This firmware exists for three reasons:

1. **It removes a dependency on someone else's release page.** If a tag moves or a
   binary stops matching the server, the project stalls. Source you can build does
   not have that failure mode.
2. **It is wire-compatible**, so it is a drop-in either way: it emits exactly the
   ADR-018 UDP frame the RuView sensing server parses
   (`magic 0xC5110001`, 20-byte header, int8 I/Q pairs), and the same frames can
   be consumed directly by `esp32-csi-node/tools/csi_probe.py` for debugging with no server at
   all.
3. **It is a thing you built**, which matters for a research write-up: the CSI
   capture path, the traffic generation that makes CSI arrive at a steady rate,
   and the framing are all decisions you can defend rather than a black box.

## Status, stated plainly

Builds clean on ESP-IDF v5.4.2 for both the ESP32-S3 and the classic ESP32
(WROOM-32). Flashed and booted on an ESP32-D0WD-V3; **not yet validated streaming
CSI against an AP** — treat the first `tools/csi_probe.py` output showing a
steady frame rate as the real acceptance test. Other IDF versions may differ in
one CSI struct; §Troubleshooting in the node README covers it.
